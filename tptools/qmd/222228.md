Tool Call Results not visible in audit log; there are DB issues with it.

The LLM audit log does not include tool call results, which really hinders its usefullness:
Digging into it, there are fundamental data storage issues:

## Bug: Tool Results Not Visible in AI Calls Audit View

### Summary

When inspecting an agent execution in the AI Calls audit view (/scaf/audit?tab=ai-calls), tool call
inputs are shown but their outputs are never displayed. There is no "Tool Results" section — only a
"Tool Calls" section showing what the agent requested. You cannot see what the tool actually returned.

---

### Observed Behavior

For an execution with multiple LLM calls, each call shows:

- Prompt — the full message history sent to the model
- Response — the model's text response (if any)
- Tool Calls — the tool invocations the model requested, e.g.:

json
[
{
"id": "tooluse_RG0JEGJUom0AUL7K5tcMur",
"name": "execute_bash",
"input": {
"command": "date '+%Y-%m-%d %H:%M:%S'",
"study_id": "cn-012-0022_Gold_Std_ws"
}
}
]

No "Tool Results" section ever appears. The output of execute_bash — an error, a timestamp, file
contents — is invisible.

────────────────────────────────────────────────────────────────────────────────

### Expected Behavior

After each "Tool Calls" section, a "Tool Results" section should display what the tool returned:

[tool_result error: id=tooluse_RG0JEGJUom0AUL7K5tcMur]
Error: execute_bash: chdir /Users/jeffwinkler/cdrdata/cn-012-0022_Gold_Std_ws: no such file or
directory

This is essential for understanding what the agent actually did and why it took subsequent actions.

────────────────────────────────────────────────────────────────────────────────

### Root Cause

#### Layer 1 — UI template

The template (audit.templ) conditionally renders Tool Results only when ToolResultsPretty != "". If that
field is empty, the section is omitted. No display bug — just nothing to show.

#### Layer 2 — Database: tool_results column is always empty

Querying the ai_audit_log table directly confirms:

sql
SELECT id, length(tool_calls) as calls_len, length(tool_results) as results_len
FROM ai_audit_log
WHERE execution_id = ;

id   | calls_len | results_len
-------+-----------+-------------
13511 |       148 |           0
13512 |       148 |           0
13513 |       148 |           0
13518 |         0 |           0

Every entry has tool_calls populated but tool_results is always empty.

#### Layer 3 — The data exists but is dropped in transit

auditing_provider.go::writeAudit() correctly extracts tool results from the last user message and sets
entry.ToolResults:

go
entry := &models.AIAuditLog{
ToolCalls:   redactForAudit(toolCallsJSON, redactPHI),
ToolResults: redactForAudit(toolResultsText, redactPHI), // ← correctly set
}

The data is also visible embedded in the next call's prompt_text (verified in DB), confirming tool
results are present in the message history at write time.

The field is dropped at the transport layer in two separate paths:

Agent path (CLI, HTTP, MCP bridges → Manager):

┌───────────────────────────────────────┬──────────────────────────────────────────────────────────────┐
│ File                                  │ Problem                                                      │
├───────────────────────────────────────┼──────────────────────────────────────────────────────────────┤
│ internal/shared/proto/audit_event.go  │ LLMCallAudit struct has no ToolResults field                 │
├───────────────────────────────────────┼──────────────────────────────────────────────────────────────┤
│ internal/engine/client/audit_store.go │ ClientAuditLogStore.Create doesn't forward entry.ToolResults │
├───────────────────────────────────────┼──────────────────────────────────────────────────────────────┤
│ internal/manager/handlers/agent_api.g │ RecordLLMCall handler doesn't map audit.ToolResults →        │
│ o                                     │ entry.ToolResults                                            │
└───────────────────────────────────────┴──────────────────────────────────────────────────────────────┘

Container path (standalone agent container → Manager):

┌──────────────────────────────────────────────┬───────────────────────────────────────────────────────┐
│ File                                         │ Problem                                               │
├──────────────────────────────────────────────┼───────────────────────────────────────────────────────┤
│ internal/manager/containers/reporter.go      │ Local LLMCallAudit struct has no ToolResults field    │
├──────────────────────────────────────────────┼───────────────────────────────────────────────────────┤
│ internal/manager/handlers/container_handler. │ llmCallAuditRequest and LogLLMCall handler missing    │
│ go                                           │ ToolResults                                           │
└──────────────────────────────────────────────┴───────────────────────────────────────────────────────┘

The direct DB path (manager-embedded agent) works correctly — AIAuditLogRepository.Create persists the
full models.AIAuditLog including ToolResults. The column exists in the schema.

────────────────────────────────────────────────────────────────────────────────

### Fix

No DB migration needed. Five targeted changes:

1. Add ToolResults string to proto.LLMCallAudit
2. Forward ToolResults in ClientAuditLogStore.Create
3. Map audit.ToolResults in agent_api.go::RecordLLMCall
4. Add ToolResults to reporter.go::LLMCallAudit
5. Add ToolResults to container_handler.go::llmCallAuditRequest and LogLLMCall
